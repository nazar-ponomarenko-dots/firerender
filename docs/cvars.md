# Консольные переменные (cvar'ы)

Справочник по всем переменным движка. Источник истины — вызовы
`cvar_register` / `cvar_register_ex` / `cvar_register_string`
(`src/cvars.c:56-107`); в игре полный список с текущими значениями даёт
команда `cvarlist`, справка по конкретной — `help <имя>`.

## Как это работает

| Механика | Поведение |
|---|---|
| Архивация | Переменные с флагом `CVAR_ARCHIVE` пишутся в `config.cfg` **только если отличаются от дефолта** (`console.c:1018-1039`). `cfg save` / `cfg load` — ручное управление. |
| Диапазон | `cvar_register_ex(name, def, min, max, …)`; `min > max` означает «без ограничений» (`cvar_register` и `cvar_register_string` регистрируют именно так). При установке значение зажимается (`cvars.c:147-150`). |
| Читы | Флаг `CVAR_CHEAT`: переменная не меняется, пока `sv_cheats 0` (`cvars.c:143-146`). |
| Повторная регистрация | Если имя уже есть (создано `config.cfg`, `map.json` или Lua), слот **усыновляется**: обновляются дефолт/диапазон/флаги, но текущее значение сохраняется (`cvars.c:60-72`). Поэтому порядок инициализации модулей важнее «второго» объявления. |
| Незнакомое имя | `cvar <имя> <значение>` для несуществующей переменной создаёт её с пометкой `map/lua-переменная` и **без** `CVAR_ARCHIVE` — опечатка не осядет в конфиге (`cvars.c:126-139`). |
| Строковые | `CVAR_STRING`: `name` (имя игрока). Число и строка держатся в синхроне. |
| Значения по умолчанию карт | Секция `cvars = { … }` в `map.json` применяется при загрузке мира и перекрывает движковые дефолты (до 64 имён, `mapdata.c:965-975`). |
