# Ловушки: доказанные НЕ-баги и известные ограничения

Раздел существует, чтобы агент **не тратил правки на несуществующие дефекты** и не
принимал как баг то, что является осознанным решением. Каждый пункт проверялся по
коду (и, где требовалось, санитайзерами).

---

## 1. Не «чинить» — это не баги

| Заметка «пахнет багом» | Почему это не так |
|---|---|
| `events.c:50-64` — кольцо отложенных событий, «переполнение молча теряет событие» | `events_emit_deferred()` **не имеет ни одного вызывающего** — только объявление в `events.h:49` и упоминание в комментарии `main.c:728`, где происходит `flush`. Мёртвый путь, а не утечка событий. |
| `game.c:244-247, 276-279` — «указатель на мир/камеру живёт через `console_exec` (UAF)» | Код **сам** это учитывает: `console_exec` может выгрузить мир (`map X`), поэтому позиция передаётся **копией**, доступ к камере — только при живом `g->cam` (`game.c:276-279` и комментарий там же), а данные действий карты — статические массивы (`MAP_ACTIONS_MAX`), не heap. Реального UAF нет; остаётся косметический эффект смены карты из триггера — он известен и вне объёма. |
| `main.c:600-613` — «cvar'ы принудительно ре-синхронизируются каждый кадр, странно» | **Намеренно:** без принудительного ресинка `sync_cvars`, не видя «изменения», не приводил `g_shadow_on`/туман в соответствие с режимом — CSM рисовался впустую в режиме blob/выкл, туман застревал в режиме из инициализации. Буквы `FR_TEST=s/o` применяются **после** этого ресинка именно поэтому (`main.c:617`). |
| `entity.c` — «serial переполняет 16 бит, хэндл завернётся» | Обёртка serial недостижима: 256 слотов, serial растёт по числу спавнов на слот. Реальным дефектом было **знаковое** упаковка/сравнение (хэндл становился отрицательным при `serial ≥ 32768`, а `entity_get` отбраковывал `handle <= 0` — живая сущность «умирала» для Lua). Исправлено: упаковка через `unsigned`, негодный хэндл — строго `0`. |
| `loading.c` — «экран загрузки не качает события → зависание/реентерабельность» | Экран загрузки не вызывает обработчики, способные повторно войти в загрузку. Реентерабельности нет. |
| `shader.c` — «циклические `#include` шейдеров зависнут» | Глубина вкладки ограничена (8): цикл даёт **ошибку компиляции GLSL** с сообщением, а не зависание. |
| `config/menu.json` — «файл не читается, удалить» | Движок его действительно не читает, но файл может использоваться сборкой APK. Не удалять; статус помечен в README. |
| `renderer.c` — «MSAA-резолв происходит даже когда пост-проходы выключены» | Условие `need_depth` (`renderer.c:940-945`): полноэкранный blit глубины пропускается, если не нужны GI / мокрый SSR / воксельный туман. Это экономия, а не оплошность. |

## 2. Реальные дефекты, уже исправленные (не вносить «поправку» заново)

| Где | Что было | Что теперь |
|---|---|---|
| `glb.c`, `glb_anim.c` — чтение GLB-чанков | `off + clen > filesz` на `unsigned` переливалось, мнимый `bin_len ≈ 4 ГБ` проходил проверки → чтение за heap-буфером | проверка вычитанием: `clen > filesz - off` |
| `glb.c:read_vertex`, `glb_anim.c:rvv` | `VEC4`-акцессор писал 4 float в `float p[3]` → порча стека | акцессоры сверяются с ожидаемым числом компонент (`ap->vec != 3`, `au vec==2`, `aj/aw vec==4`), несоответствие — «примитив пропущен» + лог |
| `glb.c`, `glb_anim.c`, `audio.c`, `hud.c` | размаршаленные `malloc`/`SDL_LoadWAV_IO`/`stbtt_MakeGlyphBitmap` (в т.ч. запись `out->nodes` до проверки `out`) | guard сразу после alloc, освобождение того, что принадлежит функции, обнуление счётчиков |
| `cvars.c:cvar_slot_new` | слот из `realloc` с мусором; «усыновление» существующего слота ставило `CVAR_STRING` без обнуления → `strcmp(c->str, c->def_str)` в `cvar_save_config` читал мусор и внедрял его в `config.cfg` | `memset(c, 0, sizeof *c)` при выдаче слота |
| `render_ctx.h` + `renderer.c` | мёртвое поле `refl_cubemap_dirty`, которое только обнулялось | удалено (кубомап воды **статический**, см. §3) |

## 3. Известные ограничения — принимать как факт

- **`SDL_VIDEODRIVER=dummy` не поддерживает GL.** `SDL_CreateWindow failed …
  driver (dummy)`, `exit 1`. CI терпит через `|| true`, поэтому «basic test» в CI
  покрывает только путь до создания окна. Headless-рендер = `offscreen` (работает
  без `DISPLAY`).
- **Кубомапа отражений воды статическая.** Грани пишутся командой
  `cubemap_capture` в `cubemaps/` и загружаются при старте; в кадре кубомапа
  **не перерисовывается**. Не «чинить» как устаревшее — это конструкция.
- **Vulkan — только поднятие device** (`srender_vk.c`), остальное заглушки.
  **Metal — каркас** (`srender_metal.c`). **Web/Emscripten — цели в Makefile нет.**
- **Юнит-тестов и тест-фреймворка нет**; `console_selftest` — единственный
  встроенный набор проверок. Не создавать `tests/`, `make test`, gtest-обвязку.
- **`LICENSE` в репозитории нет** — права не заявлены. Не добавлять файл и не
  придумывать лицензию без явного решения пользователя.
- **`objects[].rot` парсится (`mapdata.c:678`), но рендером не применяется** —
  биллборд-объекты ориентируются по камере/рельефу. Описано в docs/map-json.md;
  «исправлять» молча не надо, это заметка, а не задача.
- **Коллизия объектов — цилиндр** (`objects.c:311-317`, `x/z/radius`): высоты и
  наклона нет. Для точных форм — `collisions[]`.
- **SDL3 сам утекает ~256 байт на выходе** (внутренние потоки) — поэтому в CI
  `detect_leaks=0`. Это не код проекта.
- **`make` по умолчанию перепекает свет всех карт** (`BAKE ?= 1`); каждый `make`
  также инкрементирует номер сборки → меняются `buildnum.txt`/`src/buildnum.h`
  (оба в `.gitignore`).
- **Headless-прогон перезаписывает `config.cfg`** и пишет PNG в `screenshots/` —
  побочный эффект, а не «грязное дерево».
- **Две косметические аномалии шапок:** `linalg.c` назван в баннере `math.c`,
  у `lowend_profile.c` пустая вторая строка баннера. Правки не требуют.
- **`veg_gpu_driven_todo.txt` — план пользователя.** Пункты ЭТАПА 1 уже выполнены
  (desktop-контекст поднят до GL 4.5 CORE в `main.c:485`, `g_gl_gpu_driven` и
  GPU-driven трава работают), открыты ЭТАП 5 и 6.1/6.3/6.4. Содержимое файла не
  переписывать без спроса.

## 4. Типовые регрессии, которые легко внести

1. **Новый `gl*`-вызов без проверки `p_glXxx == NULL`** → падение на GLES/Android.
   Обязан быть в таблице `gl_loader.c` и фолбэк.
2. **Граница через сложение** (`off + len > size`) — беззнаковое переполнение
   отменяет проверку. Только вычитанием.
3. **`char buf[N]` + `snprintf` в цикл без проверки возвращённой длины** — тихое
   обрезание путей (`resources_*`, `map%d.zip`).
4. **Частично заполненная структура при неудачном alloc** — обнулять счётчики,
   иначе `*_free` и последующие циклы пройдут по мусору.
5. **Аллокация/чтение в цикле кадра** — `p95/p99` деградация при том же среднем.
6. **Новый fullscreen-проход «для постоянства»** — минус десятки fps; всегда
   условие `*_is_on()`/cvar, как в `need_depth`.
7. **Указатель на камеру/мир, переживающий `console_exec`** — команда `map X`
   выгружает сцену посреди вашей функции. Копия значения + проверка живости, как
   в `game.c:276-279`.
8. **Обнуление чужого `config.cfg` / коммит `screenshots/`** — результат прогонов,
   в git не идёт.

## 5. Как правильно «найти баг»

Прежде чем править:

1. Прочитать **весь** путь данных (парсер → структура → потребитель), а не строку,
   которая «выглядит подозрительно».
2. Проверить, есть ли у подозрительного кода **вызывающие**. Мёртвый путь — не баг,
   а кандидат на удаление (удаление — только по запросу).
3. Воспроизвести: минимальный битый файл / команда / `FR_TEST`-буква, и **лог**, а
   не только код возврата.
4. Санитайзер как в docs/testing.md §4 — он отличает реальную порчу памяти от
   «некрасивого кода».
5. Если дефекта нет, а непонятно зачем нужен код — **спросить пользователя или
   задокументировать**, а не «упрощать». Примеры такого кода — §1.
