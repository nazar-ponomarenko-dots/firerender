# Соглашения кода и документации firerender

Что читать агенту перед правкой, чтобы дифф выглядел как написанный местным.
Все пункты — описание фактического состояния `src/` (72 модуля, ~32k строк `.c`),
а не пожелание.

---

## 1. Язык и границы

- **Только C.** C++/STL/RTTI/шаблоны — нет. Комментариев `/* */` почти нет (8
  файлов), стиль — `//`.
- **Новых зависимостей нет.** Вендорится исключительно в `third_party/` (`lua`,
  `miniz`) и только с явного согласия пользователя. `third_party/SDL/` —
  скачиваемый исходник, в git не входит (`.gitignore`).
- **Сборка — одна команда gcc** по `src/*.c` + вендорные файлы
  (`CFLAGS` — `Makefile:41`, правило сборки — `Makefile:79`):
  `-O2 -Wall -Wextra -Ithird_party -Ithird_party/lua -Ithird_party/miniz -Isrc
  $(pkg-config --cflags sdl3)`. Никаких новых флагов,
  `-lGL`, GLEW, EGL — GL грузится через `SDL_GL_GetProcAddress` (`gl_loader.c`).
  Свой хук для флагов — `EXTRA_CFLAGS`.
- **Предупреждений `-Wall -Wextra` не прибавляется.** Чужой существующий шум не
  «починить» попутно.

---

## 2. Формат файлов

```c
// ============================================================================
//  renderer.c — оркестрация рендера кадра (см. renderer.h)
// ----------------------------------------------------------------------------
//  Вынесено из main.c: обход дерева сцены с профилированием, каскад
//  постобработки (…) и 2D-оверлеи (…).
// ============================================================================
#include "renderer.h"

#include "app.h"
#include "console.h"
```

- Шапка: рамка `// ===`, строка `модуль.c — что делает (см. модуль.h)`, потом
  `// ---` и 1–5 строк **«зачем этот модуль и почему он именно такой»** (обычно —
  из чего выделен, что заменяет, какой обход драйверов).
- Сначала **свой** заголовок, пустая строка, затем остальные по алфавиту.
- Отступы — **4 пробела, табуляции отсутствуют** (во всех `src/*.c`). Фигурные
  скобки в стиле K&R, `if (x) return NULL;` допустим на одной строке для тривиальных
  guards.
- Заголовки: `#ifndef ИМЯ_H` / `#define ИМЯ_H`, без `#pragma once`; объявлений,
  не нужных наружу, не выставлять; краткий русский комментарий у каждой функции.
- Одна функция — одна ответственность; длинные блоки комментируются по-русски
  **пояснением причины**, а не пересказом кода.

## 3. Именование

| Что | Стиль | Пример |
|---|---|---|
| функции | `snake_case`, глагол | `shadow_toggle()`, `resources_resolve_path()` |
| статические внутри файла | `s_` + существительное | `static Cvar *s_cvars;`, `static int s_n;` |
| глобальные состояния | `g_` | `g_gl_gpu_driven`, `g_act[A_COUNT]` |
| типы-структуры | `PascalCase`, часто self-typedef | `typedef struct Entity Entity;` |
| поля | `snake_case` (или короткие `x, y, z`) | `c->minv`, `cam->yaw` |
| константы лимитов | `*_MAX` в заголовке модуля | `CVARS_MAX`, `DECALS_MAX`, `MAP_MAX_ROADS` |
| enum-значения | `UPPER_SNAKE` с префиксом области | `PROF_SKY`, `APP_PLAY`, `CVAR_ARCHIVE` |
| GL-поинтеры | `p_gl*` | `p_glDrawElementsIndirect` |
| cvar'ы | домен_имя | `r_veg_falloff_mult`, `sv_cheats`, `cam_sensitivity` |
| команды | нижний регистр, глагол | `toggle_shadows`, `cubemap_capture` |

Префиксы доменов: `r_` рендер, `sv_` симуляция/сетевой-задел, `cam_` камера,
`cl_` клиент, `snd_` звук, `ui_`/`hud_` интерфейс, `host_` цикл.

| `engine.*` для Lua | регистрация функций + песочница | `src/lua_engine.c` |
| букву `FR_TEST` | `fr_test_apply()` / цикл | `src/main.c:232-345`, `617`, `696-760` |

## 5. Ресурсы, файлы, ассеты

- **Чтение файлов — только через `resources.c`** (`resources_read_*`,
  `resources_resolve_path`). Прямой `fopen(путь)` ломает zip-паки карт и Android
  (`assets` неизменяемы).
- **Отсутствие файла — норма:** вернуть `NULL`, залогировать, продолжить;
  отсутствующая текстура = `img/notfound.png`. Ничего не выдумывать про данные.
- **Все внешние байты — недоверенные.** Проверять размер до чтения, границы —
  вычитанием (`clen > filesz - off`), ожидаемый `vec` компонента, индексация в
  пределах буфера. Битый файл обязан дать сообщение в лог и пропуск элемента.
- **`malloc`/`free` — стандартные** (535 вызовов); `SDL_free` только там, где
  память выделена SDL-функцией (`SDL_LoadWAV_IO` → `SDL_free` в `audio.c`).
  После каждого alloc — немедленный guard; при неудаче освободить **всё**, что
  уже принадлежит функции, и обнулить счётчики.
- **JSON читается через арену** (`src/json.c`, `json_free`) — не `strdup` на узел.
- **`assert()` и `exit()` в `src/` нет** — и не должны появляться: headless-прогон
  должен вернуться с кодом, а не убить процесс.

## 6. GL и RHI

- Новый GPU-код — через `sr_*` (`src/srender.h`); `srender_gl.c` — единственный
  полноценный бэкенд. Vulkan/Metal — не трогать без отдельной задачи.
- Любой прямой `gl*`-вызов обязан существовать в `gl_loader.c` и **не вызываться,
  если `p_glXxx == NULL`** (фолбэк-путь для GLES/старых драйверов).
- GLES ≠ desktop: оговорки по `GL_INVALID_OPERATION` из-за depth-текстуры вместо
  depth-RBO (MSAA/HiZ), отсутствие части desktop-форматов. Проверять через
  `make gles` + headless-прогон.
- **Шейдеры — один исходник на все бэкенды**, `shader.c:70-75` подставляет
  `#version` (300es/310es/330core/430core). Не плодить варианты файлов.
  Hot-reload шейдеров/текстур работает в desktop-цикле раз в 1 с (`main.c:623-632`).
- Состояние GL — через `material.c` (uniform'ы, blend, depth); не «выставил и
  забыл»: любой глобальный режим обязан быть восстановлен до конца кадра.

## 7. Производительность как часть стиля

- Тяжёлая работа вне кадра: `src/jobs.c` (мини-пул потоков) или фазы загрузки с
  бюджетом. В кадре — без аллокаций на каждый объект и без `glReadPixels`/
  `glMapBuffer`.
- Дорогой визуальный режим обязан иметь cvar-выключатель и (желательно) слот в
  `profiler`, иначе его нельзя измерить и нельзя откатить на «КАРТОШКЕ».
- Числа до/после — в отчёте (`FR_BENCH`, docs/testing.md §5). «Стало красивее»
  без цифр не принимается.

## 8. Логи и сообщения пользователю

- `SDL_Log("…")` — технические события и ошибки, текст по-русски, с именем
  подсистемы: `cvar_set: "%s" не зарегистрирован — создаю%s`,
  `примитив пропущен …`. Для юзера в консоли — `console_print()`.
- Предупреждение о нештатной ситуации обязано быть таким, чтобы по нему можно было
  написать проверку в тесте (стабильная подстрока, имя проблемного пути).
- Спам в кадре запрещён: лог из цикла по 60 раз в секунду превращается в шум и
  стоит времени; логируем факт/первый случай.

## 9. Документация

- Справочники: `docs/cvars.md`, `docs/commands.md`, `docs/map-json.md`,
  `docs/lua-api.md`. Правило: **каждая строка справочника имеет `файл:строку` в
  коде, и каждый новый cvar/команда/ключ/`engine.*` появляется в справочнике в том
  же изменении.**
- Обзор и запуск — `README.md`; правила для агентов — `AGENTS.md`;
  `docs/architecture.md`, `docs/testing.md`, `docs/conventions.md`,
  `docs/pitfalls.md`.
- Честный статус: не называть работающим то, что заглушка (Vulkan — поднятие
  device, Metal — каркас, Web — отсутствует, `config/menu.json` движок не читает).
- Язык документации — **русский**, термины движка как в коде (`cvar`, `bind`,
  `чанк`, `биллборд`). Не переводить имена файлов и идентификаторов.
- Не выдумывать: прежде чем написать «движок делает X», найти X в коде.

## 10. Git

- Коммитить **только по явной просьбе**. Не пушить, не создавать ветки/PR самим.
- Стиль сообщения: `feat:`/`fix:`/`perf:`/`ui:` + что и зачем по-русски, одна-две
  строки, `git log -8` как образец.
- Не тащить в индекс: `config.cfg`, `save.cfg`, `screenshots/`, `models/`,
  `reference/`, `build/`, `buildnum.txt`, `src/buildnum.h` (`.gitignore`),
  `third_party/SDL/`.
- Не переписывать историю (`amend` опубликованного, `reset --hard`) и не обходить
  хуки без запроса.
- Перед широким `git add` — `git status` и проверка, что не попали секреты или
  артефакты прогонов.
