# AGENTS.md — правила работы для ИИ-агентов

Это рабочий контракт, а не реклама. Если правило противоречит задаче — сначала
правило, потом задача. Если не уверены, что правило применимо, проверьте факт в
коде, а не в этом файле: ссылка на `файл:строку` всегда важнее пересказа.

## 0. Иерархия приоритетов

Каждое решение взвешивается в этом порядке, сверху вниз:

1. **Стабильность движка.** Никаких падений, UB, порчи стека/кучи, «зависаний на
   загрузке», чёрных кадров. Движок обязан пережить битый ассет.
2. **FPS и время кадра.** Изменение не должно молча съесть производительность.
3. **Корректность картинки.**
4. **Красивый код / рефакторинг / новые фичи.**

«Красивее» никогда не перевешивает «не падает» и «не тормозит». Косметический
рефакторинг 45k строк рабочего рендера — это риск без профита, его не делать.

## 1. Всегда тестировать. Без исключений

Никакая правка не считается готовой, пока не получено доказательство. Минимальный
контур — три команды (CI проверяет только сборку и запуск до создания окна,
см. docs/testing.md §1):

```sh
make BAKE=0                                                       # собралось чисто
SDL_VIDEODRIVER=offscreen FR_TEST=SlS ./build/firerender          # рендер + glb + анимация
SDL_VIDEODRIVER=offscreen FR_TEST=Sx ./build/firerender           # самотест консоли и cvar'ов
```

`offscreen` рисует без `X`/`Wayland`; буква `S` в конце обязательна — она даёт
автоскриншот на 450-м кадре и выход на 480-м, иначе headless-прогон не завершится
сам и понадобится `timeout`.

Что обязательно к проверке по типу задачи:

| Затронуто | Чем доказывать |
|---|---|
| парсеры ассетов (`glb*.c`, `mesh.c`, `mapdata.c`, `json.c`, `audio.c`, `world.c`) | сборка + `FR_TEST=Sl` + санитайзер-прогон на **битом** файле (см. docs/testing.md §4) |
| рендер-конвейер, шейдеры, постпроцессы | `FR_TEST=S` до/после, сравнить `screenshots/*.png` глазами + `FR_BENCH` |
| производительность | `FR_BENCH=1` на **реальном** выводе (x11/wayland/устройство) — под `offscreen` кадр почти ничего не стоит и цифры несравнимы (docs/testing.md §5). p50/p95/p99 в отчёт, не «стало быстрее» |
| консоль, cvar'ы, команды | `FR_TEST=Sx`, затем новая команда/ценная переменная реально из консоли |
| Lua | `FR_TEST=S` (загружается `lua/main.lua` + `lua/maps/<map>.lua`) и вызов из консоли |
| физика/игрок/HP | `FR_TEST=SH` (рэгдолл), `SR` (верёвка), `SK` (киллкемера) |
| GLES-путь | `make gles` + `FR_TEST=S`, не только desktop GL |

Правила доказательства:

- **Читайте лог, а не только код-статус.** Успешный `exit 0` с новым
  `примитив пропущен`, `shader link failed`, `cvar_set: ... не зарегистрирован`
  или warning'ом компилятора — это провал, а не успех.
- **Не верьте CI-дыму на словах.** `SDL_VIDEODRIVER=dummy` не создаёт GL-окно
  (`SDL_CreateWindow failed ... driver (dummy)`, `exit 1`); CI терпит это через
  `|| true`. Реально рисует только `offscreen`.
- **Предупреждений `-Wall -Wextra` не должно прибавиться.** Их и изначально быть
  не должно; чужой шум не «починять» попутно.
- **Sanitizer для всего, что трогает чужие байты** (парсеры, `memcpy`, касты,
  индексация). Рецепт — docs/testing.md §4.

## 2. Код должен быть тестируемым из CLI

Движок живёт в headless-режиме: если фичу нельзя включить, измерить и снять с
помощью переменных окружения и консоли — фичу нельзя проверить. Поэтому:

- **Любая новая грань качества = cvar.** Регистрируется в `src/cvars.c` через
  `cvar_register`/`cvar_register_ex`/`cvar_register_string`, с `min/max`,
  `CVAR_ARCHIVE` и русским `help`. Тогда она проверяется из консоли, попадает в
  `config.cfg` и в [docs/cvars.md](docs/cvars.md). Флаг-константа в коде —
  плохо; `r_ssr 0..1` — хорошо.
- **Любое новое действие = консольная команда** (строка в таблице `s_cmds`,
  `src/cmdreg.c:42`; обработчик — в своём модуле), а не только кнопка меню.
  Команда вызывается из Lua, из конфига, из скрипта-обёртки A/B-теста.
- **Новый визуальный режим — буква в `FR_TEST`** (`fr_test_apply`, `src/main.c:232`)
  по образцу существующих: `s`/`o`/`r`/`v`/`p`/`q`/`c`/`e`/`f`/`t`/`k` — это
  тумблеры подсистем «поверх режима», ровно то, что нужно для A/B-кадров.
- **Точка обзора задаётся извне**: `FR_MAP=<имя>`, `FR_POS="x,z[,yaw,pitch]"`,
  `FR_W`/`FR_H`, `FR_MSAA`. Не захардкодить камеру в тестовом коде.
- **Делайте сброс состояния доступным:** узел/подсистема обязана переживать
  выключение на лету (`shadow_toggle`, `voxfog_set_mode`, `r_baked_light 0/1`) —
  это и фича для юзера, и тестовый рубильник.
- **Производительность — тоже CLI:** `profiler` (тайминги по слотам, GPU-queries),
  `matlist`, `FR_BENCH=1`, `FR_BENCH_GPU=1`, `FR_BENCH_PRESET=N`. Новый дорогой
  проход обязан быть виден в профиле, иначе его нечем мерить.
- **Fail-soft с логом, а не с `assert`.** Плохой ассет — сообщение в лог и пропуск
  элемента; в headless-тесте это видно по stdout. `abort()`/тишина — непроверяемо.

## 3. Бить работу на подзадачи

Правило: одна подзадача = одна проверяемая гипотеза.

- До начала работы распилить список (`TaskCreate`), у каждой — **что делаю, чем
  доказываю готовность**. Порядок depend'ов, если часть А блокирует часть Б.
- Не смешивать в одном проходе: правку памяти + переименование + новый фича-флаг.
  Каждой категории — свой шаг и своя проверка, иначе регрессия неотличима от
  случайного совпадения.
- **Минимальная правка в существующем стиле** важнее архитектурно верной.
  Исправлять переполнение — одной строкой условия, а не переписыванием парсера.
- Размер: если подзадача не проверяется одной командой из §1, она слишком крупная.
- После каждой подзадачи — сборка и smoke-прогон, а не «сделаю всё, потом
  починю». Половинчатых состояний в дереве не оставлять: либо узел работает, либо
  его честно нет в путях сборки.
- Не «подчищать» за предыдущим шагом, заметив посторонний дефект: завести задачу и
  сказать пользователю. Попутные правки — источник незапланированных регрессий.

## 4. Стабильность: конкретные обязательства

Проверено на этом коде (см. историю правок и docs/pitfalls.md):

- **Каждый `malloc`/`realloc`/`SDL_malloc` проверен сразу после вызова.**
  Никакого `out->x = malloc(...)` до `if (!out)`. При неудаче — освободить всё,
  что уже принадлежит функции (`json_free(); free(bvs); free(file); return NULL;`),
  и обнулить счётчик, чтобы последующие циклы не крутились на мусоре.
- **Границы из файла — только вычитанием, никогда сложением.** `clen > filesz - off`,
  а не `off + clen > filesz`: беззнаковая сумма переливается и проверка проходит.
- **Любой размер из внешнего файла сверять с фактическим буфером и с ожидаемым
  `vec`-компонентом** (`acc_fits` + `ap->vec != 3`; 4 float в `float p[3]` — порча
  стека, а не «странная модель»).
- **Слоты из `realloc` — с мусором:** обнулять структуру целиком (`memset`), если
  часть полей строковая и читается позже (`cvar_slot_new`, `strcmp` в
  `cvar_save_config`).
- **Хэндлы/UID не знаковые.** Упаковка `serial<<16|num` через `int` умирает на
  `serial >= 32768`; контракт «0 = негодный» держать явно (`src/entity.c`).
- **Указатели через выгрузку мира:** `console_exec` способен выполнить `map X` и
  убрать сцену. Поэтому — копия значения вместо указателя и проверка живости
  узла/камеры перед использованием (образец: `src/game.c:276-279`).
- **GL-состояние:** контекст GLES ≠ desktop. Новый вызов обязан быть в таблице
  `gl_loader.c` и обязан не вызываться, когда `p_glXxx == NULL` (фолбэк-путь) —
  иначе падает на Android/старых драйверах. Проверять `GL_NO_ERROR` не «для
  красоты», а там, где дальше читается буфер.
- **Ничего не выдумывать про данные.** Отсутствие файла — штатная ситуация:
  `img/notfound.png`, сообщение в лог, продолжение работы.

## 5. FPS: за что движок платит

Прежде чем добавить проход, понять, сколько он стоит на fill-rate. Дорогое в этом
проекте (в порядке убывания типичной цены):

- **fullscreen-проходы в пост-цепочке** (GI с темпоральным накоплением, SSR,
  воксельный туман 3×R8 3D, bloom). Один лишний экран = минус десятки fps.
- **Трава/растительность** — overdraw. Есть z-prepass травы (`r_veg_zprepass`),
  GPU-driven compute-cull (`shaders/veg_cull.cs`) + `glDrawElementsIndirect`,
  бюджет регенерации чанков (`r_veg_regen_budget`), `r_veg_falloff_mult`.
  Не добавлять инстансы «пока просто».
- **MSAA на GLES** — inversion: depth-RBO вместо depth-текстуры (HiZ). Не «улучшать»
  мультисемплинг без замера на GLES.
- **Тени**: CSM, режим статических/запечённых теней, «пятна». Каждый каскад —
  полный проход сцены.
- **Разрешение**: динамическое — `r_dynamic_resolution` + `r_dynamic_target_ms`
  (`src/lowend_profile.c`), пресеты `КАРТОШКА/СРЕДНИЕ/УЛЬТРА` (матрица 21 cvar —
  docs/cvars.md), общий масштаб `r_render_scale`. Правильный ответ на
  «тормозит» — выключить/понижать через cvar, а не переписать проход.

Обязательства:

- **Любой «улучшили картинку» сопровождается числом `FR_BENCH`** до и после —
  снятым на реальном выводе, не на `offscreen` (docs/testing.md §5).
  Нет чисел — нет правки.
- **Тайминг работы вне критического пути:** тяжёлые задачи в `src/jobs.c`
  (мини-пул потоков) или в фазах загрузки с бюджетом; не в кадре.
- **Минимизировать аллокации на кадр** и пересылку данных GPU↔CPU; `glReadPixels`,
  `glMapBuffer` в цикле кадра — красный флаг.
- **Не вводить новую синхронизацию «на всякий случай».** Фиксированный тик логики
  (100 Гц desktop / 60 Гц Android, максимум 8/4 тика) — контракт; долгая логика
  ловится `sim_acc` клиппингом, а не новым потоком.

## 6. Границы технологий

- **Только чистый C** (стиль проекта), никаких C++/STL/RTTI. Никаких новых
  зависимостей: вендорится исключительно в `third_party/` (`lua`, `miniz`) и только
  с явного согласия пользователя.
- **SDL3 и OpenGL — единственные системные вызовы** ввода/окна/звука/GL. GL-функции
  грузятся в рантайме через `SDL_GL_GetProcAddress`; линковать `-lGL`/GLEW/EGL
  нельзя.
- **Весь GPU-код идёт через RHI `sr_*` (`src/srender.h`).** Прямые `gl*` допустимы
  там, где уже есть (`gpu_gl.c`, специфика GLES), но новая подсистема — через `sr_*`,
  иначе её нельзя перенести.
- **Vulkan/Metal — не «доделать попутно»**: `srender_vk.c` поднимает device,
  остальное заглушки; `srender_metal.c` — каркас. Это отдельные большие задачи.
- **Ресурсы читаются только через `resources.c`** (`resources_read_*`,
  порядок pak → диск → `base_dir` → `../`). Прямой `fopen(path)` ломает
  Android/zip-паки.
- **Шейдеры — один исходник на все бэкенды**: `shader.c` подставляет `#version`
  (300es/310es/330core/430core). Не плодить `.glsl`/`.glessl`-варианты.
- **Lua — песочница** (`src/lua_engine.c`): без `dofile`/`loadfile`/`load`, лимиты
  на число объектов; новый `engine.*` регистрируется + в docs/lua-api.md.

## 7. Сборка и git

- `make` **по умолчанию перепекает свет всех карт** (`BAKE ?= 1`, штамп
  `build/.baked.stamp`) — минуты работы. Для итерации по коду: `make BAKE=0`.
- Целевые сборки: `make gles`, `make linux`, `make win`, `make apk`,
  `make mapzip MAP=…`, `make mapbake MAP=…`, `make bake-maps`, `make backends`.
- **`buildnum` инкрементируется каждым `make`** → меняется `src/buildnum.h` и
  версионная строка. Это ожидаемый дифф, не править вручную.
- **Коммитить только когда пользователь явно попросил.** Не пушить, не создавать
  PR/ветки без запроса.
- Перед `git add` — `git status` и посмотреть, что попало. Не тащить в индекс:
  `config.cfg`, `save.cfg`, `screenshots/`, `models/`, `reference/`, `build/`,
  `buildnum.txt`, `src/buildnum.h` (список в `.gitignore`).
- **Headless-прогон перезаписывает `config.cfg` и складывает PNG в `screenshots/`**
  — это побочный эффект тестирования, файлы в git не идут; не «случайно» не коммитить
  их и не удалять чужие.
- Никогда не `--no-verify`, не `reset --hard`/`checkout --`/`clean -f` без явного
  запроса; перед ними — `git status` и сохранение чужого незакоммиченного.
- Сообщение коммита — по стилю репозитория: префикс `feat:`/`fix:`/`perf:`/`ui:` +
  что и **зачем** по-русски (`git log -8` как образец).

## 8. Документация — часть задачи

- Каждая новая **cvar/команда/ключ `map.json`/`engine.*`-функция** обязана появиться
  в соответствующем docs-файле в том же изменении. Строка справочника без кода и
  код без строки справочника — одинаковый дефект.
- Не утверждать про фичу, что она работает, если в коде заглушка. Статус бэкендов
  (GL/GLES — работает, Vulkan — device-only, Metal — каркас, Web — нет) обязан
  оставаться честным в README.
- Прочитать вслух своё утверждение и найти ему `файл:строку`. Не «похоже, что»,
  не «обычно в таких движках».
- Комментарии в коде — русские, и только про **почему** (скрытое ограничение,
  инвариант, обход конкретного бага). То, что **что** делает код, уже видно по
  именам. `// TODO на будущее` без задачи не добавлять.

## 9. Запрещено без явного запроса пользователя

- Рефакторинг «для чистоты», переименования по всей кодовой базе, смена стиля.
- Удаление/правка `veg_gpu_driven_todo.txt` — это план пользователя (обсуждать, но
  не решать за него).
- Создание `LICENSE` и любых «надо бы» файлов (`.editorconfig`, CI, тестовый
  фреймворк) — сначала спросить.
- Установка/обновление системных пакетов, скачивание зависимостей из интернета.
- Новая зависимость, новый язык, новый рендер-бэкенд, новая папка `src/`.
- «Исправление» доказанных НЕ-багов — список в docs/pitfalls.md.

## 10. Чек-лист сдачи

1. `make BAKE=0` — собралось, **новых warning'ов нет**.
2. Headless-дым: `SDL_VIDEODRIVER=offscreen FR_TEST=SlS ./build/firerender` —
   `exit 0`, в логе нет новых `failed`/`пропущен`.
3. Целевая проверка по таблице §1 (A/B-скриншот или число `FR_BENCH`).
4. Санитайзер-прогон, если тронуты чужие байты.
5. `config.cfg`/`screenshots/`/`build*` — не в diff'е; временные файлы убраны.
6. Docs обновлены в том же коммите; каждая ссылка на фичу ведёт в код.
7. Отчёт пользователю: что изменено, **чем доказано** (команды + числа/файлы),
   что осталось непроверенным. Если проверка не выполнена — сказать прямо.
